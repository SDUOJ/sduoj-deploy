## 1. 当前状态

现有资源已具备 rooms、roster parse、容量/禁用座位、seat assignment/bind-course、TEST 证书、formal_ack、监控与 roster 导出。monitor_data 的 WORKING/SUBMITTED 来自答题卡，不是在线会话；Java getOnlineSessions 目前为 SUPERADMIN 单用户管理入口。

账号生成、密码条和监考能力是提案；本地 cs25problem 的脚本与模板是需求线索，不直接认定它们已经接入 OJ 或在所有环境可复用。

## 2. 账号台账与导入恢复

### 2.1 生成规则

- 前缀 5 位 + 随机后缀 7 位，共 12 位；若前缀策略变化，整体仍符合 OJ 4–16 位用户名限制。后缀字母表 acdefhjkmnprtwxy，使用密码学随机数，不使用可预测的 random。
- 密码 12 位，字母表 ACDEFHJKMNPRTWXY；生成前验证当前密码策略，不能把单次本地成功当作永久规则。
- `(exam_id,candidate_no)` 唯一且 candidate_no 为文本，保留前导零。重复请求复用原 username/password，不重新随机。
- username 在本台账唯一还不等于 OJ 全局可用；创建前检查碰撞，外部冲突不覆盖旧账号，未绑定成功前才可在持久化事务中分配新名称。
- 先持久化加密凭据和 generation/version，再调用 OJ 或渲染。Fernet/密钥版本、备份恢复与导出访问单独通过 SECRETS 门禁；不得把明文放进 TaskJob、事件、日志或模型上下文。

### 2.2 账号导入状态机

```text
prepared -> import_pending -> importing -> imported
                              |              |
                              `-> unknown <--'（回包丢失）
                              `-> failed/conflict
```

台账为每人记录 attempt、请求摘要、导入身份、receipt 与最后错误。导入批次也有幂等键。网络超时、部分成功或用户名已存在时先按受控接口查验；不能直接重放 addUsers、重置别人的密码或把失败当成功。既有批量接口是否全事务、是否覆盖已有账号须在隔离环境验证，未证实前按非幂等外部写处理。

OJ UserBatchAddDTO 已要求合法且非空 email、nickname≤30、studentId≤20；其校验注解不证明注册全流程接受占位邮箱或一定不会发信。占位地址为独立待确认政策：先用隔离 Java/数据库、禁发外部邮件验证一次合法/非法/重复导入与登录，不能拿真实考生或生产账号探测。

材料只从已导入且读回核对的冻结台账生成。导入未知的行阻止发布/打印，允许导出脱敏错误清单供处理。

## 3. 材料渲染与回验

A4、3列×4行、12条/页，每考场另起页；每条含姓名、考号、考场、用户名、密码、站点网址和座号。实际模板/字体/渲染器固定版本；可使用现有 LaTeX 或经批准的渲染方案，不能把 PDF 依赖视作已部署。

| 反向校验 | 判据 |
| --- | --- |
| 页数 | 各考场 ceil(人数/12) 之和，含空位与分页规则 |
| 溢出 | 无 Overfull/Missing character；文本块在每条安全边界内 |
| 缺字 | PDF 提取与渲染检查结合，不只扫描替代字符 |
| 唯一与完整 | 全批每个考生恰一条、字段逐项匹配 manifest，不仅“页内一次” |
| 跨材料一致 | 台账、座位、签到、账号导入与密码条使用同一 roster/seat/material revision |

任一失败整批不可发布。打印按 manifest_hash 幂等，重印读原加密凭据，不生成新密码。姓名、备注等输入必须转义 LaTeX/HTML 与 CSV/Excel 公式；受限 worker 禁 shell escape/外链，控制文件大小和页数。

PDF 和台账本身含明文密码，必须私有存储、短期授权下载、no-store、下载审计与保留/销毁政策。仅“数据库加密”不保护已导出的纸张或文件。管理员先预览脱敏样张，正式材料单独确认；监考普通状态接口不返回密码。

## 4. 监考链接与会话

免 OJ 密码不是无鉴权。链接绑定 exam、明确 room scope、允许动作、有效期、次数和撤销版本；name 是自报姓名，不构成实名身份验证。

### 4.1 兑换

```text
/v2/invigilate/<link_id>#token=<one-time-secret>
  -> 前端立即移除 fragment，POST join {token,name}
  -> 原子校验有效期/revoked/max_uses并消耗次数
  -> 独立高熵会话 secret，服务端只存 hash
  -> Secure + HttpOnly + SameSite Cookie，响应 no-store
```

URL path 中的 link_id/session_id 是非秘密标识，不能单独授权；不在 query/session= 参数里放凭证。链接 secret 只存 SHA-256，不记访问日志、第三方分析或 referrer。具体 Cookie 路径与同站部署需冻结，不能与 OJ SESSION 共用名字。

每个请求重新验证 session hash、过期/撤销、原 link 和 exam 状态，session 不得晚于 link 失效。撤销 link 同时使全部子 session 失效；max_uses 在 DB 锁下计数，GET 预览不消耗。登录失败限频，不能因多人共用 NAT IP 自动认定滥用。

写接口验证 Origin/CSRF 与当前 scope；前端不能通过 room 参数、username 或 action 选择授权范围外对象。需要全场链接时是明确的 all_rooms scope，不能用 NULL/空字符串意外授予全部考场。

### 4.2 通道边界

新 `/api/ps/invigilate/**` 和实测兑换必须先过 AUTH 门禁：Java Gateway 的精确方法/路径免 OJ 登录规则、Autolab peer 校验、能力令牌中间件、业务对象校验四层一同设计。不能只在 Autolab 豁免 cover_header，却假定 Gateway 会放行，也不能把整个 /auto-task 设成匿名。

内部节点控制面与监考能力令牌不共用受众或全能 RPC token。管理入口仍用原用户会话与考试管理权限；监考会话不授予通用 OJ 管理、代码读取、成绩修改或账号操作权。

## 5. 移动界面、状态与动作

独立轻量路由，不加载管理导航；375px 真机单列卡片、44px 触控、正文≥14px、安全区适配、无横向表格。顶部显示考试/考场、统计和最后刷新时间，分段筛选异常/未观察到登录/未交卷。

| 数据 | 来源与含义 |
| --- | --- |
| session_present | Java 受控批量会话存在性，不等于人正在电脑前 |
| last_observed_at | 服务端采样时间；不能冒充 Java 未提供的 last_active_at |
| participation | 原答题卡 NOT_STARTED/WORKING/SUBMITTED |
| online_state | observed / not_observed / unknown，失败时 unknown，不把接口失败显示离线 |
| attendance | 监考登记到场/缺考，独立于登录和答题状态 |

采用按场次名单过滤的内部批量聚合：只返回布尔/时间等最小字段，不回 token、IP 或全部在线会话明细。不放宽原 SUPERADMIN 管理接口给管理组。Java 新内部入口需验证 service 身份、scope 与当前考试管理权；未经批准不通过全能内部令牌代理任意 usernames。

216 人/15s 是初始负载样例；需固定硬件和并发考场后验收 p95 目标（建议冷/热缓存分别记录，500ms 只是目标）。批量分页、短时观测缓存和失效回退，页面隐藏时停轮询，失败保留旧数据并标 stale/unknown。

| 动作 | 行为 |
| --- | --- |
| present / absent | 到场/缺考记录，受本考场与考试时间规则约束 |
| exception / resolved | 类型、备注与被处理事件 ID，保留历史，不覆盖旧记录 |
| extension_request | 登记建议补时分钟，**不自动改变考生提交时间** |

确需调整正式时间，由有权管理者在原规则下单独确认和执行，记录关联 receipt。每个动作有 request_id、expected_version、actor/session、scope 和时间，重复点击幂等、并发冲突不产生重复异常或补时。记录更正以追加事件完成。
