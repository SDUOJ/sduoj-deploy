> 目标：在既有 `exam` 资源之上补齐 **账号台账 · 密码条 · 监考端（移动优先）· 免密链接**。
>
> 既有能力（考场读取、座位分配、TEST/FORMAL 门禁、prepare/publish、监控、名单导出）**全部复用**，见 `sduoj-deploy/docs/exam-prep/`。

## 2. 账号与台账

### 2.1 规则（沿用本地已验证实践）

| 项 | 规则 |
| --- | --- |
| 用户名 | `<前缀><7 位不易混淆小写>`，共 12 位；字母表 `acdefhjkmnprtwxy` |
| 密码 | 12 位不易混淆大写；字母表 `ACDEFHJKMNPRTWXY` |
| 唯一性 | 跨校区全局唯一 |
| **幂等** | 同一考试 + 同一考号重复生成 → **复用原账号密码**，绝不重新随机 |
| 持久化 | 台账先落盘**再**渲染，保证重印一致 |

### 2.2 数据模型

```sql
CREATE TABLE oj_exam_account (
  id            VARCHAR(63) PRIMARY KEY,
  exam_id       VARCHAR(63) NOT NULL,       -- auto_task_resource.id (kind=exam)
  candidate_no  VARCHAR(32) NOT NULL,       -- 考号，文本主键
  name          VARCHAR(64) NOT NULL,
  username      VARCHAR(32) NOT NULL,
  password_cipher TEXT NOT NULL,            -- Fernet 密文
  campus        VARCHAR(32) NULL,
  major         VARCHAR(64) NULL,
  room_name     VARCHAR(64) NULL,
  seat_no       INTEGER NULL,
  oj_user_id    BIGINT NULL,                -- 导入后回填
  imported_at   DATETIME(6) NULL,
  created_at    DATETIME(6) NOT NULL,
  UNIQUE KEY uq_exam_candidate (exam_id, candidate_no),
  UNIQUE KEY uq_username (username)
);
```

**约束**：`(exam_id, candidate_no)` 唯一 → 幂等的物理保证。重印时按此键取回，**不重新生成**。

### 2.3 导入 OJ

复用 `POST /api/manage/user/addUsers`（ADMIN，JSON 数组）。字段要求：

- `username` 匹配 `^[A-Za-z0-9_]{4,16}$`（12 位符合）
- `password` 长度 4–32（12 位符合）
- **`email` 必填且须合法** → 需生成占位邮箱（如 `<username>@exam.invalid`），但须确认 OJ 是否校验域名可投递
- `nickname` ≤30、`studentId` ≤20

> **注意**：`email` 必填是硬约束。若无合法邮箱来源，需要在导入前确认占位邮箱是否被接受（**待实测**）。

## 3. 考务材料渲染

### 3.1 密码条版式（沿用本地 `slip_template.tex`）

- A4，**3 列 × 4 行 = 12 条/页**
- **每个考场另起一页**
- 页眉：`<校区> - <考场> 第 x 页 / 共 y 页`
- 每条 7 个字段：姓名、考号、考场、用户名、密码、网址、座号

### 3.2 渲染后反向校验（必须）

参考本地成熟实践，渲染完成必须自动核验：

| 校验 | 判据 |
| --- | --- |
| 页数 | 等于「各考场条数 ÷ 12 向上取整」之和 |
| 溢出 | 编译日志无 `Overfull`、无 `Missing character` |
| 缺字 | PDF 文本中无 `\ufffd` |
| 唯一性 | 每个用户名在页内**恰好出现一次** |
| 越界 | 文本块不超出条目边框 |

任一不通过 → **整批作废**，不得发出。

### 3.3 其它材料

签到表、考场安排表、用户组导入清单、账号台账（保密）——同一套数据源，一次生成，交叉核验（名单/分配/签到/台账四方一致）。

## 4. 监考端

### 4.1 使用场景

监考老师用**手机**打开专用链接 → 输入姓名 → 选择考场 → 看到本考场考生状态 → 对异常进行确认。

### 4.2 免密链接

```
https://<oj>/invigilate/<token>
```

```sql
CREATE TABLE oj_invigilator_link (
  id            VARCHAR(63) PRIMARY KEY,
  exam_id       VARCHAR(63) NOT NULL,
  room_name     VARCHAR(64) NOT NULL,        -- 空 = 全部考场
  token_hash    VARCHAR(64) NOT NULL UNIQUE, -- 只存哈希
  valid_from    DATETIME(6) NOT NULL,
  valid_until   DATETIME(6) NOT NULL,
  max_uses      INTEGER NOT NULL DEFAULT 0,  -- 0 = 不限
  used_count    INTEGER NOT NULL DEFAULT 0,
  revoked       TINYINT NOT NULL DEFAULT 0,
  created_by    BIGINT NOT NULL,
  created_at    DATETIME(6) NOT NULL
);

CREATE TABLE oj_invigilator_session (
  id            VARCHAR(63) PRIMARY KEY,
  link_id       VARCHAR(63) NOT NULL,
  name          VARCHAR(64) NOT NULL,        -- 监考人自填姓名
  ip            VARCHAR(64) NULL,
  user_agent    VARCHAR(255) NULL,
  created_at    DATETIME(6) NOT NULL,
  expires_at    DATETIME(6) NOT NULL,        -- 短会话，默认 8h
  revoked       TINYINT NOT NULL DEFAULT 0
);
```

**安全要求**：

1. 令牌 **32 字节随机**，库里只存 `sha256`，明文仅生成时显示一次。
2. 有效期**由考务设定**（默认考试开始前 30 分钟 ~ 结束后 30 分钟）。
3. 会话令牌与会话 Cookie 分离，**不授予任何 OJ 权限**，只授予「本考场只读 + 异常确认」。
4. 可随时吊销（改 `revoked=1`）。
5. 所有访问记录 IP/UA，异常（同一令牌多 IP）标记。

### 4.3 监考端界面（移动优先）

```
┌──────────────────────────┐
│ 考场：青岛 A301           │   ← 顶部固定
│ 考试：2026 预推免机试     │
│ 14:05  ·  已登录 213/216  │
├──────────────────────────┤
│ [全部] [异常] [未登录] [未交卷] │  ← 分段筛选
├──────────────────────────┤
│ 3 号  张三  ● 已登录 ✓已交 │
│ 5 号  李四  ● 未登录  ⚠   │
│ 8 号  王五  ● 已登录 未交  │
└──────────────────────────┘
```

**移动适配要点**：

- 单列卡片列表（非表格），触控目标 ≥44px
- 顶部统计条固定，滚动时可见
- 每行右侧「确认」按钮 → 底部弹出操作面板
- 无横向滚动；字号 ≥14px
- 支持下拉刷新 + 15s 自动轮询

### 4.4 监考动作

| 动作 | 语义 | 是否落库 |
| --- | --- | --- |
| 确认到场 | 该考生已到考场入座 | ✅ |
| 记录异常 | 迟到/设备故障/身体不适/疑似违规/其它 | ✅ 必填类型 + 备注 |
| 确认已处理 | 异常已解决 | ✅ |
| 登记补时 | 因故障补时 | ✅ 需填写分钟数 |
| 标记缺考 | 考试结束仍未到 | ✅ |

```sql
CREATE TABLE oj_invigilator_action (
  id            VARCHAR(63) PRIMARY KEY,
  exam_id       VARCHAR(63) NOT NULL,
  session_id    VARCHAR(63) NOT NULL,
  room_name     VARCHAR(64) NOT NULL,
  username      VARCHAR(32) NULL,
  action        VARCHAR(24) NOT NULL,   -- present|exception|resolved|extension|absent
  exception_type VARCHAR(32) NULL,
  note          TEXT NULL,
  minutes       INTEGER NULL,
  created_at    DATETIME(6) NOT NULL,
  INDEX ix_action_exam (exam_id, created_at)
);
```

## 5. 考生状态聚合

监考端需要三类状态，来源不同：

| 状态 | 来源 | 判定 |
| --- | --- | --- |
| **是否登录** | `GET /manage/user/getOnlineSessions?username=` | 有活动会话 |
| **是否在作答** | `ProblemSetAnswerSheet.finish != 1` 且记录存在 | `WORKING` |
| **是否交卷** | `ProblemSetAnswerSheet.finish == 1` | `SUBMITTED` |
| 未开始 | 无记录 | `NOT_STARTED` |

新增聚合接口（服务端逐考场批量查，避免 N+1）：

```
GET /auto-task/ai/exams/{id}/rooms/{room}/status?session=<监考会话>
→ { rows: [{seat, name, username, online, submission, last_active_at, actions:[...] }],
    summary: {total, online, submitted, exceptions} }
```

**性能**：216 人 × 每 15s 轮询，必须一次性批量取在线会话（Java 侧需要一个按用户列表查询的内部接口，或对 `getOnlineSessions` 增加 `usernames` 批量参数）。

## 6. 接口清单

### 6.1 考务管理端

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| `POST` | `/auto-task/ai/exams/{id}/accounts/generate` | 管理组 | 生成账号（幂等） |
| `GET` | `/auto-task/ai/exams/{id}/accounts` | 管理组 | 账号列表（密码**默认脱敏**） |
| `GET` | `/auto-task/ai/exams/{id}/accounts/export` | 管理组 | 导出保密台账（记审计） |
| `POST` | `/auto-task/ai/exams/{id}/accounts/import` | 管理组 | 批量导入 OJ |
| `POST` | `/auto-task/ai/exams/{id}/materials/render` | 管理组 | 生成密码条/签到表 |
| `GET` | `/auto-task/ai/exams/{id}/materials/{kind}` | 管理组 | 下载（`kind=slip|signin|roster`） |
| `POST` | `/auto-task/ai/exams/{id}/invigilator-links` | 管理组 | 生成监考链接 |
| `GET` | `/auto-task/ai/exams/{id}/invigilator-links` | 管理组 | 链接列表与使用情况 |
| `POST` | `/auto-task/ai/exams/{id}/invigilator-links/{linkId}/revoke` | 管理组 | 吊销 |

### 6.2 监考端（免密，令牌鉴权）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/invigilate/links/{token}` | 校验链接，返回考试名与可选考场 |
| `POST` | `/invigilate/links/{token}/join` | `{name}` → 返回会话令牌 |
| `GET` | `/invigilate/sessions/{sid}/rooms/{room}/status` | 考场实时状态 |
| `POST` | `/invigilate/sessions/{sid}/actions` | 记录动作 |

> 这组接口放在 `/api/ps/invigilate/**` 下，**不走** `SDUOJUserInfo` 鉴权，改用令牌中间件；必须**显式豁免**网关身份头要求，并纳入 `main.py` 的 peer 校验范围。

### 6.3 学生侧（不变）

`/v2/problemSet/<psid>/overview` 等既有路径不变。

## 7. 前端

- **管理端**：`/manage/exam/prep` —— 考务准备工作台（名单→账号→考场→材料→链接）。
- **监考端**：`/invigilate/:token` —— 独立于管理端布局的单页应用路由，移动优先。
- 监考端**不加载管理端导航**，减少体积；路由层面单独 `lazy`。

## 8. 实施顺序

| 步 | 内容 | 验收 |
| --- | --- | --- |
| 1 | 在线状态批量查询接口 | 216 人一次查询 < 500ms |
| 2 | 账号生成 + 台账 + 幂等 | 重复生成密码不变 |
| 3 | 账号批量导入 | 抽样登录成功 |
| 4 | 密码条渲染 + 五项反向校验 | 故意造错能被拦下 |
| 5 | 监考链接 + 会话 | 令牌过期/吊销即失效 |
| 6 | 监考端页面（移动优先） | 真机 375px 宽可用 |
| 7 | 异常记录与补时 | 记录完整、可导出 |

## 9. 风险

| 风险 | 缓解 |
| --- | --- |
| 免密链接泄露 | 短有效期 + 吊销 + IP 记录 + 令牌只存哈希 |
| 监考端误操作 | 关键动作二次确认；全部落库可追溯 |
| 密码明文外泄 | 默认脱敏；导出需权限 + 记审计 |
| 在线状态不准 | 明确标注「最后活跃时间」，不做绝对判断 |
| 占位邮箱被拒 | 导入前先测一条 |
