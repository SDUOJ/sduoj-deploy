# 03 出题平台

> 统一检索与工作台，不合并原始题库、评测和答题卡。统一模型不能覆盖源系统的权限或把学生题面与作者答案混为一种详情。

## 1. 当前模型与安全前置

| 项 | 编程题 | 客观题 | 主观题 |
| --- | --- | --- | --- |
| 原始权威 | Java oj_problem 及题面/测试点关系 | Autolab problem_objective | Autolab problem_subjective |
| 原始身份 | problemId / problemCode | pid + objective 类型 | pid + subjective 类型 |
| 归属 | userId、managerGroups（多组）、isPublic | username；引用题组的管理权限 | 同左 |
| 独立存在 | 能 | 表结构及 add 路径能独立存在，但缺统一独立列表/工作台 | 同左 |
| 题组 | 原业务引用 | group.type=0 | group.type=1 |

两个 native 表 pid 可同号，这是类型化 ID 的正常情况，裸 pid 才会产生歧义。group.type=2 表示编程题，不可复用新的反向数字枚举。

### 1.1 原生关联缺口（S1-02/S1-03）

info/edit 先经 Depends→group_base_info/edit→group_manager 验证 gid 权限，故不能宣称“任意登录者”。但后续模型只按 pid 查/改，没有验证该题是否属于这个 gid、类型是否匹配。具备一个合法题组管理权限的主体可能组合另组 pid；add/edit 题组也未见逐题引用授权。

先单独提出 AUTH 修复：认证主体、gid 管理权限、题组类型、gid/pid 实际关联、目标题源权限在同次操作验证；info 和 edit 都覆盖。学生只通过原答题卡路径拿按考试状态裁剪的内容。公开列表不能成为获取 answer/judgeConfig 的旁路。

### 1.2 编程题现状

ProblemService.queryProblemByPage/queryByCode 已有公开、本人、管理组和超管入口。四者不是四个持久化 visibility 数值：superadmin 是角色覆盖，管理组是显式 ACL。仍需 S1-04 验证缓存撤权、组集合键碰撞及数据下载等敏感读，不能据列表谓词宣布整条权限链已正确。

## 2. ID 与兼容契约（S1-05）

| 表达 | 语义 |
| --- | --- |
| uid | prog:<decimal problemId> / obj:<decimal pid> / subj:<decimal pid> |
| kind | program / objective / subjective 字符串 |
| native_id | 源系统主键，JSON 中用字符串；不把 problemCode/提交 hex ID 强转 |
| group_native_id | 管理题组主键 |
| group_position / problem_position | 个人显示顺序中的下标，必须经过原映射解析 |
| scope_item_key | 冻结的题单/比赛题项上下文，不单以 uid 合并重复引用 |

原学生 `(psid,gid,pid)` 路由继续工作，适配层显式映射到真实 gid/pid，并考虑 shuffle、题组复用、同题多次出现与指定题面。新接口不靠改字段名混用两种语义。

## 3. 权威、投影与 ACL

### 3.1 统一索引

oj_unified_problem 放在 Autolab 侧，保存类型化引用、标题、来源签名、同步时间、删除标记及检索 ACL 投影，DDL 见 [06](06-数据库变更汇总.md)。接口通过 Autolab 聚合，路径唯一见 [07](07-API清单.md)；原 Java /problem 和 /manage/problem 接口不改归属。

Java 数据由经批准的适配 RPC/事件或批量增量读取同步，不直读/直写另一数据库。同步采用游标和 tombstone，定期对账；故障重跑幂等。每次返回敏感详情或执行写入都回源校验，索引陈旧不得继续授予权限。无法核验则失败或省略该项，不能泄露“私有题存在”及其标题/答案。

分页若回源过滤导致短页，返回准确 has_more/cursor；不把扫描过但无权限的数量作为 total 泄露。避免每条无界 RPC，提供有界批量源校验与失败指标。

### 3.2 可见性和管理权分开

| 来源 | 普通阅读 | 编辑/答案/测试数据/引用 |
| --- | --- | --- |
| 公开 | 允许读取公开题面；匿名读取需单独批准精确入口 | 属主、现有显式管理组、超管；普通引用者不能因此编辑或读答案 |
| 组内 | 属主、指定管理组、超管 | 各动作仍走源权限；引用不自动转授管理权 |
| 私有 | 属主和超管 | 同左；历史显式组授权按兼容映射保留，不静默撤销 |
| 超管 | 既有角色覆盖 | 使用原角色含义，审计敏感操作 |

Java 多组不能压成一个 manage_group_id。公开题已授权的管理组编辑权也不能被新表“公开仅属主”覆盖。界面可把私有+管理组显示为“组内”，不强制新增 Java visibility 枚举。

对外详情定义 learner（题干/允许样例）、author（答案/评分标准/完整数据）和 exam-context（原时间/成绩/答案发布策略）三种投影。不能凭 include_tests=true、source=group 或 public 访问 author 投影。

### 3.3 历史数据迁移

原生新增 title、visibility、manager_group_ids、difficulty 均允许 NULL 表示未迁移。旧读路径先保留；新读路径对 NULL 按原合法关联与主体权限处理，而非直接当公开或拒绝全部组成员。

回填时核验 creator username 到稳定 userId 的映射，收集多个**合法**管理组，不随意挑第一组；孤儿题、无有效属主、跨组冲突或可疑引用出隔离清单，人工确定。不能把未经验证的任意历史引用变成新共享授权。逐题记录迁移前后可见/可编辑集合及签名，只有等价验证通过才切读。原稿“visibility=0 + 单组回填即行为不变”撤回。

### 3.4 混合题组是独立后续能力

统一列表不要求立刻支持混合题组。先交付统一视图，保留原 group.type。

如放开混合：题项新增字符串 kind、稳定 slot_id 与 group_format_version；无 kind 时显式映射旧 0→objective、1→subjective、2→program。所有读者先支持，包括学生随机顺序、题面、权限、计分、正式提交/Run、评阅、统计、导出及缓存。

确认全链兼容后才能开启新写；旧读者不能通过忽略未知字段读取混合题，必须拒绝或使用仍懂格式的回退版本。写入混合数据后，不能承诺回滚到任意旧镜像。S4-09 单独开关/PR/验收。

## 4. 九阶段出题工作台

沿用 AiResource/AiRevision 和原 authoring native-plan/native-finalize；新 package 只存阶段、固定 manifest 与发布 receipt，避免复制两份可变正文权威。

| 阶段 | 必须产物 | 准入 |
| --- | --- | --- |
| idea | 考察点、来源、预期难度 | 人确认目标 |
| spec | 输入输出、范围、边界、评分与限制 | 题意冻结到版本 |
| statement | 原文、样例、题面语言和附件 | 与 spec 版本一致 |
| metadata | 标签/难度/来源/模板/分值 | 源权限与类型校验 |
| programs | 生成器、validator、标程与可选 checker | 编译成功，固定 digest |
| data | 数据/答案、每点哈希与生成 seed | 来源程序版本固定 |
| audit | 七项自动检查证据 | 全部针对同一 manifest |
| human | 真实独立试做记录、意见 | 指定测试人完成当前版本 |
| published | 源题/题组/附件 receipt 与读回结果 | 人工批准并核对版本 |

stage 是服务端状态机，不能通过 POST 一个 stage 字符串跳过检查。修改题意、程序、数据或目标配置必须使相关终检和实测失效；不把旧绿勾带到新版本。

### 4.1 七项终检

| 项 | 可验证证据 |
| --- | --- |
| 题面逻辑 | 范围/约束/spec 一致，样例跑出预期结果；歧义标人工复核 |
| 数据分布 | 每个子任务的规模/边界/分布统计及生成来源，不只查看随机 seed |
| 配置可靠性 | 读回模板、限制、checker、测试点和分值，与待发布 manifest 对照 |
| 多语言 | 按题目要求的语言集合提交矩阵；豁免需人确认并留下理由 |
| 解法多样性 | 不同算法标程及典型错误解的预期得分矩阵 |
| 数据强度 | 暴力/错误解在指定反例上的实际结果 |
| 边界条件 | 最小/最大规模、退化与极端值覆盖清单 |

人类实测是第八类独立检查，不计入“七项自动化”。它有助于发现歧义，但不能称“唯一手段”或保证发现全部问题。每个适用题型有自己的检查 profile；客观/主观不强行套编程语言矩阵，不适用项须批准而非伪造通过。

### 4.2 发布与不确定结果

publish 绑定 expected_version、manifest_hash、target 与 operation_key。复用原 TEST/FORMAL 或 native-plan/finalize 门禁；读回每个源 ID/附件签名后才 published。

Java 调用、对象上传与 Autolab DB 不是一个事务。阶段 receipt 持久化，失败保留为 partial/unknown；先读回对账。若原写接口没有可靠幂等键，应先增加受限幂等支持或人工对账，不能在外层重试 create 并声称 exactly-once。发布前始终保持私有 staging；不把半成品题或测试数据临时公开。

## 5. 人类实测链接

邀请绑定 package_version、manifest 和题型/配额，使用 32 字节随机能力令牌，只存 token_hash、有效期、次数、撤销状态。URL 用前端 fragment 交换受限会话，不把明文令牌放进 API 路径、日志或 referrer；具体入口先过 AUTH 门禁。

v1 一份邀请对应一位测试人、最多一次成功兑换和一个独立会话；多人测试生成多份邀请，不共用同一链接轮流覆盖 session。max_attempts 限该测试人的作答次数，与兑换次数分开。邀请自身 version 可变，package_version 是不可变题包绑定，两者不能混用。兑换时锁定邀请行并原子消耗次数/写会话 hash；重复兑换仅已持有有效会话者可继续，丢失兑换结果且无会话时由管理者撤销旧邀请、重新生成，不能无条件覆盖会话。

- 免 OJ 登录不等于无鉴权。每次访问都校验有效邀请、快照和提交上限，只能读自己的题面与结果。
- 在隔离试做副本执行，不占用正式提交次数，不写正式答题卡或比赛成绩，不返回隐藏答案/数据。
- 服务端计时。编程题保留每次代码/语言、任务时间和得分；客观题保留选项，主观题保留文本/文件引用。记录不可覆盖，固定产物哈希。
- 意见、测试人数与完成条件可配置；意见必填的验收不能被模型自动代写。自报姓名标为自报，不当成实名证据。
- 管理者能列出当前包的邀请与已授权结果，单独撤销某一邀请；关联 package/trial 和 invitation.expected_version 均校验并递增邀请 version，幂等撤销立即使该邀请的已兑换会话失效。operation_key 和结果写入原包审计事件，重复撤销读回已撤销结果。原始代码/答案仍限原管理权限，列表不返回令牌。撤销不依赖更改整个题包版本或等待过期。
- 试做执行有频率、CPU、输出和费用上限；邀请泄露、过期、撤销、跨题/跨版本/重复提交均有反例。

## 6. 原生题与文档管线

客观题保持现有 type=单选/多选/不定项；图片选项、explanation 等扩展先做旧 JSON 兼容读取。主观题保持文本/文件/验收队列与多项 rubric，不能让统一草稿覆盖旧 judgeConfig。

```text
上传 -> 类型/大小/展开限制 -> 原文件只读归档
     -> 分页/段落/图表提取 -> OCR/版面 -> 题块切分 -> schema 校验
     -> 人工核对 -> 翻译对照 -> 显式导入草稿
```

复用现有 files/upload 与 documents parse 资源，不虚构一个已存在的 documents/upload。具体第三方库和语言包以锁文件/镜像为准，导入成功不等于已安装 OCR 或已支持扫描 PDF。

输入支持原有 PDF/DOCX/图片/MD/TXT，保留已支持 PPTX 路径；拒绝伪装类型、压缩炸弹、外部关系/宏、路径穿越。解析在受限 worker，禁用文档中 URL 的自动抓取。模型解析/OCR 输出是不可信内容。

每块保留 source_file_hash、page、坐标系/bbox、文本或 image_ref、提取器版本与 confidence；不把无置信度的结果伪装成 0.93。人工修订记录版本。

翻译按块新增语言版本，不覆盖原文；保存术语表、模型/提示词和源版本，公式/代码/数据范围保持。切换源版本后旧译文显示过期。导入/发布分别确认。

## 7. 前后端与实施

统一题目中心三 tab：公开题库、我的组、我的；超管额外全部。原编程题 /problem/:ProblemCode 和题单地址保留；新 /problem-library/:uid 不与它冲突。

统一 API 由 Autolab 聚合，Java 继续权威管理编程题；完整接口见 [07](07-API清单.md)，路由及字段裁剪 UI 见 [08](08-前端改造方案.md)。

先安全关联/缓存 → 类型化 ID → 可重建索引/历史 ACL 审计 → 兼容元数据 → 检索与工作台 → 文档/终检/实测 → 发布；混合题组独立放行。验收必须包含未登录/本人/同组/异组/撤权/超管、答案字段、随机下标、重复引用、迁移冲突和旧正式提交回归。
