## 2. 五个系统的关系

```
                    ┌──────────────────────────────────────────┐
                    │  前端 sduoj-web2 (React + AntD)          │
                    │  管理端 / 学生端 / 监考端(移动优先)       │
                    └───────────────┬──────────────────────────┘
                                    │ HTTPS，网关 :8080 /api/**
        ┌───────────────────────────┼───────────────────────────┐
        │                           │                           │
┌───────▼────────┐        ┌─────────▼──────────┐      ┌─────────▼─────────┐
│  02 AI 端口层  │        │  03 题目平台       │      │  05 考务系统      │
│  端口注册表    │        │  统一题目视图      │      │  账号/考场/监考   │
│  统一队列      │        │  三题型绑定        │      │  免密监考链接     │
│  MCP 工具网关  │        │  权限模型          │      └─────────┬─────────┘
└───────┬────────┘        └─────────┬──────────┘                │
        │ 作业                        │ 题目/题组                │ 名单/座位
        ▼                             ▼                          ▼
┌─────────────────────────────────────────────────────────────────────┐
│  01 云 Agent 运行时：harness 适配(DSH / Codex) + 沙箱 + S3 工作区    │
│  + 调度与配额 + 版本管理 + 审计                                       │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 只用 MCP 工具访问 OJ
                                ▼
                    ┌───────────────────────────┐
                    │  Java 微服务 (题目/用户/比赛) │
                    │  Autolab (题单/考试/查重)    │
                    │  filesys (对象存储)          │
                    └───────────────────────────┘
```

**关键边界**：

- **01 是执行层，不含业务语义**。它不认识「题目」「查重」，只认识「给我一个作业、一个工具集、一个工作区、一个配额」。
- **02 是接入层**，负责「哪个用户的哪个端口、跑哪个 harness、能用哪些 MCP 工具、排队与限额」。
- **03/04/05 是业务层**，它们既可以被前端直接调用（REST），也可以被 agent 通过 MCP 调用。
- 04 查重、05 考务也可完全走 02 → 01 的 agent 通道执行（例如「一键配置整个题单的查重」），但**必须保留不经 AI 的确定性路径**。

## 3. 复用与新建（先给结论）

现有 OJ 的 AI 基础设施比预期成熟得多，**大部分需求是改造而非新建**：

| 已有 | 位置 | 复用方式 |
| --- | --- | --- |
| 持久任务队列（租约 + 心跳 + Redis 唤醒 + 幂等键） | `auto_task/worker.py`、`store.py`、`entities.TaskJob` | 02 直接扩展，增加 `port_id`、端口维度限流 |
| 站点级 provider 配置（Fernet 加密、SSRF 校验、版本冲突、按用途覆盖） | `auto_task/configuration.py` | 02 提升为「多端口注册表」 |
| Docker 沙箱（network none / cap-drop / read-only / pids-limit / tmpfs） | `auto_task/sandbox.py` | 01 升级为多运行时 + 快照 + S3 挂载 |
| Codex App Server 桥接（JSON-RPC、审批、动态工具） | `auto_task/management_agent.py` | 01 抽象为 `Harness` 接口，Codex 为首个实现 |
| 资源版本 + 修订历史 + 全文检索 | `entities.AiResource`、`AiRevision` | 03/04/05 的状态载体 |
| 查重快照 + 完整性校验 + JPlag 执行 | `entities.AiPlagiarismSnapshot`、`plagiarism.py` | 04 扩展为扫描任务与绑定 |
| 考试资源 + 座位 + 测试/正式门禁 | `server/auto_task_exams.py`、`handlers.py` | 05 复用，补账号与监考 |
| 前端 AI 页面与 API 层 | `sduoj-web2/src/Pages/Manage/AI/`、`Utils/API/` | 03/04/05 沿用页面骨架与 `request` 约定 |

**必须新建**的只有五类：
1. Harness 抽象与第二实现（DSH）、版本管理与灰度（01）
2. 用户端口注册表 + 默认端口 + 端口并发限额 + MCP 网关（02）
3. 统一题目视图与所有权/可见性模型（03）
4. 查重扫描任务、阈值复核、绑定发布、学生自查回显（04）
5. 账号生成台账、密码条渲染、监考端与免密链接（05）

## 4. 全局约定（各子系统遵守）

### 4.1 身份与鉴权

| 通道 | 使用方 | 凭证 | 说明 |
| --- | --- | --- | --- |
| 浏览器 → 网关 | 前端 | Spring Session Cookie `SESSION` | 现有方式，不改 |
| Autolab → Java | 服务间 | `sduoj-token` 内部 RPC header | 现有 `sduojApi.py`，不改 |
| **agent → MCP → OJ** | 智能体 | **代表用户身份** | 见下 |

**MCP 的身份模型（02 的核心约束）**：
- Agent 进程**永不持有**用户 Cookie 或内部 token 以外的任何长期凭证。
- MCP 工具调用由 **Autolab 侧**作为调用代理：Autolab 以「发起该作业的用户」身份调用 OJ，调用前校验该用户的当前权限。
- 用户的 OJ 会话若已失效，MCP 调用**立即失败并终止作业**（不降级、不续期），符合「权限与用户相同」。
- 所有 MCP 写操作记审计：`subject_id`、`tool`、`arguments_hash`、`result_code`、`resource_version`。

### 4.2 数据分区

- **对象存储 / 工作区**：`s3://<bucket>/tenants/<tenant>/<kind>/<id>/`，`kind ∈ {agent-workspace, problem-asset, exam-material, plagiarism-report, submission-archive}`。
- **数据库**：Autolab 用独立 MySQL（现有 `:7360`），Java 用主库（`:3306`），互不跨库写入。
- **队列**：MySQL 为唯一权威，Redis 仅作唤醒提示（沿用现有设计，见 `store.py` 顶部注释）。

### 4.3 错误与状态码

统一沿用现有约定：业务成功 `code == 0`；权限 `403`；冲突 `409`；资源不存在 `404`；限额 `429`；上游失败 `502`。前端 `request.ts` 已按此解包，新接口不得自创包体。

### 4.4 前端

- 页面注册：`src/Config/router/routerM.tsx`（管理端）与 `router.tsx`（学生端），路由需带 i18n key。
- API：`src/Utils/API/*.ts`，统一 `request.get/post`。
- 文案：`src/Assert/lang/zh.json` + `en.json`，新增 key 必须同时补齐两种语言。
- 新页面沿用 `Pages/Manage/AI/` 的卡片 + 表格 + 弹窗表单模式；移动端页面单独放 `Pages/Invigilator/`。

## 6. 已确认的安全问题（先于一切新功能）

本方案的现状核对发现 **4 个可实际利用的问题**，它们与需求无直接关系，但会直接影响新系统的安全性。**任何涉及这些面的新功能都必须在其后上线。**

| # | 问题 | 位置 | 影响 | 归属任务 |
| --- | --- | --- | --- | --- |
| 1 | 网关对等校验只覆盖 `/auto-task`，`/management-agent` 可绕过 | `sduoj-autolab/main.py:31` | 管理 Agent 路由可被直连访问 | `S1-01` |
| 2 | `/ps/objective/info`、`/ps/subjective/info` 无归属校验 | `server/objective.py:30`、`model/objective.py:9` | **知道 `pid` 即可读到正确答案** | `S1-02` |
| 3 | 题组可引用他人私有题 | 题组侧无 `isPublic` 校验 | 私有题被他人题单暴露 | `S1-03` |
| 4 | `(psid,gid,pid)` 双语义（下标 / 主键） | `model/answer_sheet.py:529` | 易写出改错题的缺陷 | `S1-05` |

第 2 条是本轮**唯一确认可直接利用的信息泄露**，修复量很小（加一次可见性判定），应优先处理。
