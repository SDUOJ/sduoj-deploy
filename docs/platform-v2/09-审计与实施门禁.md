## 4. 发布、迁移与回滚矩阵

1. 冻结组件 SHA、接口包坐标、依赖与镜像 digest；保持原生产者发布链，不引入源码额外 checkout/composite build。
2. 备份并恢复到隔离环境，检查旧表字符集/主键类型、孤儿与多组冲突，记录计数与哈希。先部署兼容读者，再执行经批准的 additive migration。
3. 分批回填，逐批检查游标、ACL 等价与输入哈希；不能把“默认私有 + 填一个组”称作行为不变。
4. 默认关闭新入口；用最终制品跑真实 MySQL/Redis/MQ、Java/Autolab、网关/WebSocket 与浏览器业务链。SQLite/mock 只证明合同，不能证明行锁、网络隔离或真实授权。
5. 灰度启用每个领域开关。混合题组写入、匿名令牌和自动 MCP 写能力分别放行，不随 AI 页面一起解除 devOnly。
6. 回退先关闭新写入口、取消/排空任务并核对不确定写结果，再切回仍兼容新数据的应用版本。保留表、账本、账号和材料清单，禁止线上直接 DROP 或自动重置账号密码。

## 5. 最小评审与验收包

- 一个 PR 一个目的：安全绑定、端口/额度、harness、题目 ACL、查重发布、考务导入分别拆开；SQL 不与无关功能打包。
- 每任务有 repositories、depends_on、approval_gates、acceptance、rollback；执行者 auto/agent 只表示建议分工，不表示自动批准或自动发布。
- 标记 done 前，前置任务须 done 或有理由的 not_applicable；verification.evidence 按 positive/negative/failure_recovery 各记录 artifact、sha256、source_commit、tested_at（UTC ISO 秒）、result=pass，并为各 approval_gates 记录 approval_refs。校验器只检查记录形状，审查者仍须打开证据、核实哈希/主体/版本与实际批准；任意字符串或形式正确的假记录不能代替验收。
- 各阶段必须有 P0 反例、状态转换、并发/重放/故障恢复、权限撤销和旧业务回归。无真实环境证据时明示未验收。
- 接受未知/失败状态，不用“未发现异常”“已离线”“已导入”替代信息不足；验收报告写清样本、版本和检查边界。
