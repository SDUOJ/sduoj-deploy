## 当前合同

`oj_unified_problem` 只保存三题型检索元数据，不保存答案、rubric、测试数据或学生作答。身份为 `prog:<id>` / `obj:<id>` / `subj:<id>`；源系统/题型约束、`kind/ref_id` 唯一键、InnoDB、二进制排序和 enforced CHECK 已在真实隔离 MySQL 验证。Long 使用十进制字符串。

新增表已从旧 AI migration 的 TABLES 集合移出，只能显式迁移；`auto_task.unified_migration` 默认 dry run，apply 只接受 `SDUOJ_MODE=debug` 的专用 loopback 随机测试库。已有不兼容 schema 会阻断，不自动 ALTER。审阅 SQL 为 `docs/sql/20261019_unified_problem.sql`。

| 通道 | 当前行为 |
| --- | --- |
| Java `GET /internal/problem/queryUnifiedPage` | 必须恰好一个正确的原内部 token；通过既有未缓存 `/internal/user/runSubject` 解析当前角色，仅超管能读取完整快照。以 `afterId/pageSize` keyset 分页，每页最多 100；闭合返回 ID、标题、属主、公开标志、管理组和 canAuthor。 |
| Java `POST /internal/problem/verifyUnifiedRefs` | 同样检查 token 和当前身份；最多 100 个十进制字符串 ID，调用原 `ProblemCommonService.isProblemManager`。learner 允许公开或原管理权限，author 仅原管理权限；删除/无权对象省略。空 ID、重复 ID、非规范数字和未知 view 拒绝。 |
| Autolab 原生源 | 对 objective/subjective 分别按 pid keyset 扫描；独立题保留给原作者。管理组仅来自题目作者拥有的同型原生组，伪造引用不增加授权。原生元数据尚未迁移，visibility 仍为 NULL，不虚构公开状态。标题暂由原题干首行裁剪，tags/difficulty 保留空值，不属于 S4-02。 |
| AutoLab `GET /auto-task/ai/library/problems` | 原登录身份 + fresh 身份；source=public/group/mine/all，all 仅当前超管。每批最多 100 个对象回源，单请求最多扫描 1000 个索引候选；短页可以返回继续扫描的 cursor，不返回隐藏对象数量。 |
| AutoLab `GET /auto-task/ai/library/problems/{uid}` | learner/author 均读取当前源 ACL 和元数据。索引只提供候选身份，不授予权限。返回当前标题和 source_signature；索引落后时标 index_stale。author 仍只返回元数据，正文/答案等后续详情属于 S4-03。 |

读取不受 AI 账号积分、组件开关或端点配置限制。Autolab 源使用新事务，避免旧 RR/identity map 复活撤销权限；Java 在自己的服务中校验自己的数据库，AutoLab 不直连 Java 库。源故障整页 503，无私有 partial 结果或原始错误；无权/删除详情统一 404。

浏览器 cursor 使用既有 Fernet 配置加密，并绑定主体和筛选条件；不会把被过滤的私有 UID 作为 base64 明文交给客户端。换主体、改过滤器或篡改 cursor 会拒绝；每次使用仍重查当前权限。

## 完整重建与恢复

入口为原 Python 环境中的 `python -m auto_task.unified_sync --user-id <id>`，默认只读；只有加 `--apply` 才发布，建表另需 `--create-schema`。目标仍限专用 loopback 测试库，当前超管在扫描前和发布前各复核一次。

同步先读取 Java、客观题和主观题的完整 keyset 快照，再独立读取第二遍并比对 count/hash。两遍不同、任一页失败、重复引用、异常 cursor 或超限均不发布。每个源最多 50000 项/16 MiB；超限明确失败，不把截断结果叫完整。全部来源验证通过后，在一个目标事务中分批 upsert 和 tombstone；单独同步原生题型也只清理该题型，避免两题型互删。tombstone 清除旧标题、属主和 ACL 元数据。

同一目标库的命名锁阻止两个同步器同时发布。重建报告只含来源、count/hash 和 tombstone 计数；失败后从头显式重建，不重放外部写。两次扫描只能核对采集窗口内的一致性，读取路径的实时源校验继续处理此后的变化。

## 已收敛的问题与剩余出口

四项行为反例先失败再修复：单题型同步误删另一题型、独立原生题遗漏、稀疏候选后的分页丢失、源故障返回 500。旧的“按索引 ACL 返回内容”实现和不稳定 pageNow 全量快照也已替换；不再通过反复运行旧模型/探测支线验证这些问题。

仍需实际运行中的新 Java 内部 HTTP 接口与 AutoLab 组合核对；当前组合测试的 Java HTTP 对端是合成服务，身份 RPC 在 Java SQL 测试中也是替身。S1-02/04/05 的完整前置门禁仍未整体关闭，因此 S4-01 保持 in_progress，不推进 S4-02、不把平台 v2 标完成。后续只补该组合出口和前置证据，不重跑已经收敛的模型探测链。
