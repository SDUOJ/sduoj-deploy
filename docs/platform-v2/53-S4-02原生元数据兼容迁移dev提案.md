# S4-02 原生元数据兼容迁移 dev 提案

状态：待批准；不执行DDL、回填或权限变更。前置S4-01/S1-03已完成。范围只限AutoLab的`problem_objective`、`problem_subjective`及原迁移/权限适配；Java源表、匿名入口、生产、push和AI组件继续关闭。

## 最小变更

两表各增加四个nullable字段：`title VARCHAR(255)`、`visibility TINYINT`、`manager_group_ids JSON`、`difficulty TINYINT`，与06草案一致。不改原pid/username/题干/答案/config，不新增主体字段、外键或平行正文。实际SQL拆成单独migration文件，经预检才执行，不导入整份06草案。

NULL始终表示未迁移；原合法属主/同型真来源组/超管权限继续回源判定。`manager_group_ids`保存已核实多组的元数据投影，不作为授予权限的独立依据。第一批不把历史题默认改成公开或私有，`visibility`保留NULL；难度无来源也保留NULL。原标题用现有S4-01规则生成候选并限255字符，不能覆盖人工已填标题。

username仍是原权威属主字段。复用原Java身份HTTP合同解析稳定userId，报告同时记录username/userId及映射摘要；映射前后不一致、缺失/重复主体、孤儿题、外来作者引用、类型错误、畸形成员或超限均隔离，不回填、不根据这些引用新增共享权。没有新增自动Java委托或直接Java数据库读取。

## 执行与失败边界

迁移命令默认dry-run；apply只接受明确debug、loopback、自建随机数据库，禁止常规Web启动自动建列。检查MySQL版本、旧列类型/字符集/引擎、DDL权限、目标库身份和已有列精确类型。重复执行相同版本可核对后no-op；不兼容列/schema阻断，不自动修正。

先将自有合成旧库备份，验证备份hash，再恢复到另一个自有随机库。仅在恢复库执行DDL和分批回填；每批固定kind/pid游标、输入hash和预期旧值，锁后重查源组/属主，不覆盖并发人工编辑。DDL持锁时间及规模必须记录实际样本，不能宣称覆盖生产大表。中断不把partial标完成；重入从已提交批次继续并重新校验当前来源。

权限等价按每题的属主、全部真实管理组、超管和无权主体构成规范谓词集合，另以合成账号/组实测正负例。迁移前后计数/hash及授权集合必须一致；不将无限主体逐个枚举的缺失伪装成全量等价。删除、撤组和可疑引用在新旧读者中均拒绝。旧读者忽略nullable新增列后仍能info/edit/学生作答，回退保留列和迁移记录，不DROP、不覆盖备份恢复业务数据。
