# 04 查重系统

> 现状是「按单题跑一次 JPlag」；目标是「**独立的扫描任务 + 阈值复核 + 多次重扫 + 绑定发布 + 学生自查**」。
>
> 好消息：执行链（JPlag 6.3、快照不可变、完整性校验、AI 解释、失败降级）**已经很好**，缺的是任务编排与结果分发。

## 1. 现状

| 能力 | 现状 | 位置 |
| --- | --- | --- |
| 提交快照 | ✅ 不可变快照 + `sha256` 全量校验，拷贝代码后不再编辑 | `AiPlagiarismSnapshot`、`AiPlagiarismSubmission` |
| 引擎 | ✅ JPlag 6.3.0（`-n -1` 保留全部配对，`-m threshold`） | `plagiarism.py` |
| 范围 | ⚠️ **单个 `pid`**，`psid + group_id + pid` 三元组 | `/native/plagiarism/create` |
| 规模 | ⚠️ 2–1000 条（`scan` 内）；入口限制 2000 条 | 同上 |
| 阈值 | ✅ 可配 `threshold`（0–1），`similarity >= threshold` 才入选 | 同上 |
| 人工复查 | ✅ `pairs/review`，决策 `CLEAR / SUSPICIOUS / CONFIRMED` | `auto_task_actions.py:245` |
| 写回 | ✅ `writeback`，要求全部复查 + `overwrite_existing` | `auto_task_actions.py:270` |
| 报告下载 | ✅ `.jplag` 原始报告 | `auto_task_actions.py:381` |
| AI 解释 | ✅ 对每对给出「可能成因」，**明确不判处罚** | `plagiarism.py` |
| 多次查重 | ⚠️ 靠 `operation_key` 幂等；**不同参数会 409**，无「历史版本」概念 | `_plagiarism_request` 比较 |
| contest 维度 | ❌ 只认 `psid + group_id + pid`，contest 的提交不在同一路径 | — |
| 一键整单 | ❌ 无 | — |
| 绑定到题单供学生看 | ❌ 无 | — |
| 可视化 | ⚠️ 有工作台，但无「相似度矩阵/热力图」「并排 diff」 | `PlagiarismWorkbench.tsx` |
| 导出 | ⚠️ 只有 `.jplag` 原始包，无 CSV/Excel | — |
| 学生自查接口 | ❌ 无（前端只有跳转管理端的路由） | `router.tsx:127` |

## 2. 目标模型：扫描任务与绑定发布

```
扫描任务(Scan)                    绑定(Binding)
  ├ 范围: contest | 题单 | 题组 | 单题      └ 决定「学生能看到什么」
  ├ 阈值: 0.0–1.0 (1 = 不查重)
  ├ 语言: c/cpp/python/java
  ├ 多次: 同一范围可建 N 个 Scan
  └ 结果: pairs[] + 人工决策
```

**两级分离是关键**：扫描是「事实」，绑定是「发布决策」。一个题单可以有多次扫描，但最多绑定一份。

## 3. 数据模型

```sql
-- 扫描任务（一次查重）
CREATE TABLE oj_plagiarism_scan (
  id              VARCHAR(63) PRIMARY KEY,
  kind            VARCHAR(16) NOT NULL,        -- contest | problemset | group | problem
  ref_id          BIGINT NOT NULL,             -- contestId / psid / gid / problemId
  title           VARCHAR(255) NOT NULL,
  threshold       DECIMAL(4,3) NOT NULL,       -- 0.000 ~ 1.000, 1=不查重
  language        VARCHAR(16) NOT NULL,
  selection_policy VARCHAR(16) NOT NULL,       -- latest | best
  status          VARCHAR(24) NOT NULL,        -- pending|running|done|failed|cancelled
  scope_count     INTEGER NOT NULL DEFAULT 0,  -- 覆盖题目数
  submission_count INTEGER NOT NULL DEFAULT 0,
  pair_count      INTEGER NOT NULL DEFAULT 0,
  confirmed_count INTEGER NOT NULL DEFAULT 0,
  creator_id      BIGINT NOT NULL,
  task_id         VARCHAR(63) NULL,            -- auto_task_job.id
  created_at      DATETIME(6) NOT NULL,
  finished_at     DATETIME(6) NULL,
  INDEX ix_scan_ref (kind, ref_id, created_at),
  INDEX ix_scan_creator (creator_id)
);

-- 扫描覆盖的题目（支持一次扫描多题）
CREATE TABLE oj_plagiarism_scan_problem (
  scan_id     VARCHAR(63) NOT NULL,
  problem_uid VARCHAR(63) NOT NULL,            -- 统一题目 uid（03 的 oj_unified_problem）
  pid         BIGINT NULL,                     -- 客观/主观题 pid
  problem_code VARCHAR(64) NULL,               -- 编程题
  snapshot_id VARCHAR(63) NULL,                -- 该题快照
  pair_count  INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (scan_id, problem_uid)
);

-- 重复对（阈值以上）
CREATE TABLE oj_plagiarism_pair (
  id              VARCHAR(63) PRIMARY KEY,
  scan_id         VARCHAR(63) NOT NULL,
  problem_uid     VARCHAR(63) NOT NULL,
  left_uid        BIGINT NOT NULL,             -- 用户
  right_uid       BIGINT NOT NULL,
  left_submission VARCHAR(128) NOT NULL,
  right_submission VARCHAR(128) NOT NULL,
  similarity      DECIMAL(5,4) NOT NULL,
  matches         LONGTEXT NULL,               -- JPlag matches（含行区间）
  ai_review       LONGTEXT NULL,               -- 可能成因，不作为处罚依据
  ai_status       VARCHAR(16) NOT NULL DEFAULT 'none',  -- none|ready|pending|failed
  decision        VARCHAR(16) NOT NULL DEFAULT 'PENDING', -- PENDING|CLEAR|SUSPICIOUS|CONFIRMED
  decided_by      BIGINT NULL,
  decided_at      DATETIME(6) NULL,
  reason          TEXT NULL,
  INDEX ix_pair_scan (scan_id, similarity DESC),
  INDEX ix_pair_users (scan_id, left_uid, right_uid)
);

-- 决策历史（支持「后期修改比例」与改判）
CREATE TABLE oj_plagiarism_decision_log (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  pair_id     VARCHAR(63) NOT NULL,
  from_state  VARCHAR(16) NOT NULL,
  to_state    VARCHAR(16) NOT NULL,
  reason      TEXT NOT NULL,
  actor_id    BIGINT NOT NULL,
  created_at  DATETIME(6) NOT NULL,
  INDEX ix_decision_pair (pair_id, created_at)
);

-- 绑定：一个 contest/题单最多绑定一份
CREATE TABLE oj_plagiarism_binding (
  id          VARCHAR(63) PRIMARY KEY,
  kind        VARCHAR(16) NOT NULL,            -- contest | problemset
  ref_id      BIGINT NOT NULL,
  scan_id     VARCHAR(63) NOT NULL,
  visible     TINYINT NOT NULL DEFAULT 1,      -- 是否向学生展示
  show_similarity TINYINT NOT NULL DEFAULT 1,  -- 学生能否看到相似度数值
  show_code   TINYINT NOT NULL DEFAULT 1,      -- 学生能否看到对照代码
  only_confirmed TINYINT NOT NULL DEFAULT 1,   -- 仅展示已确认重复
  bound_by    BIGINT NOT NULL,
  bound_at    DATETIME(6) NOT NULL,
  UNIQUE KEY uq_binding_ref (kind, ref_id)     -- 最多一份
);
```

**唯一约束**直接落实「一个比赛或题单，最多绑定一份查重结果」。

## 4. 扫描范围与提交采集

### 4.1 四种范围

| kind | 题目来源 | 提交来源 |
| --- | --- | --- |
| `problem` | 单题 | 现有 `/internal/submission/listResult` |
| `group` | `problem_group.problemInfo` 中 `type=2` 的题 | 同上，按 gid |
| `problemset` | `problem_set.groupInfo` 中所有 `type=2` 的题组 | 同上，按 psid |
| `contest` | `oj_contest` 绑定的 `problemCode` 列表 | **Java contest 的提交**（`/internal/submission/page` by `bizType=contest`） |

> contest 是目前最大缺口：查重链路只有 Autolab 题单一条，需要补一条 Java contest 的取数路径。

### 4.2 采集规则

- **每人每题取一次**：`selection_policy=latest`（最后一次提交）或 `best`（最高分）。
- **只取已判题且有代码的提交**；编译错误可排除。
- **上限**：单题 2000 条，整单 20000 条；超限**提示缩小范围**，不静默截断。
- **快照不可变**：采集即拷贝，与后续学生再提交无关（现有 `AiPlagiarismSubmission` 已做到）。

### 4.3 语言分组

JPlag 不能跨语言比对。一个扫描任务内按语言分组分别跑，结果合并时标注语言：

```
scan → [cpp 组] → JPlag → pairs(cpp)
     → [python 组] → JPlag → pairs(python)
     → 合并 + 按 similarity 降序
```

## 5. 阈值语义

用户明确：「**1 表示不查重**，只有大于查重率才有意义」。

| threshold | 含义 |
| --- | --- |
| `1.000` | 不查重（跳过执行，直接标记 `skipped`） |
| `0.900` | 只关心几乎完全相同的代码 |
| `0.700` | 默认，平衡误报与漏报 |
| `< 0.5` | 不推荐，误报极高 |

**注意方向**：`similarity >= threshold` 才入选（现有实现已经是 `if score < threshold: continue`，正确）。用户说「只有高于查重率才有意义」与之一致。

**后期修改**：允许在扫描完成后**调整阈值重新筛选**（不重跑 JPlag，直接从全量配对重算），因为 JPlag 的 `-n -1` 已保留全部配对。这正是「后期可以修改重复判定的比例」的实现方式。

## 6. 人工复查

### 6.1 流程

```
待复查(PENDING) → 审阅(并排 diff) → CLEAR / SUSPICIOUS / CONFIRMED
                                      │
                                      └─ 可随时改判（记入 decision_log）
```

### 6.2 逐条展示

每条重复对展示：

- 两位学生的用户名、学号（按权限）
- 相似度（百分比）
- **并排代码对照**，左侧/右侧，高亮 `matches` 给出的行区间
- AI 解释（「可能原因」），**显著标注「仅供参考，不构成判定依据」**
- 决策按钮 + 理由输入（必填）

### 6.3 一键写回

复用现有 `writeback`：要求全部复查完毕，写回原生题单的查重标记。

## 7. 绑定与学生自查

### 7.1 绑定

在扫描详情页选「绑定到该题单/比赛」，可配置：

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| 是否展示 | 开 | 关 = 学生看不到 |
| 仅展示已确认 | 开 | 只暴露 `CONFIRMED` |
| 显示相似度数值 | 开 | 关 = 只显示「存在重复」 |
| 显示对照代码 | 开 | 关 = 只显示结论 |

### 7.2 学生接口（独立）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/ps/plagiarism/self/{kind}/{refId}` | 返回**当前学生本人**参与的所有重复对 |

**返回约定**：

```json
{
  "bound": true,
  "scan_title": "2026 预推免机试 · 第一次查重",
  "show_similarity": true,
  "items": [
    {
      "problem_uid": "prog:123",
      "problem_title": "某题",
      "similarity": 0.92,
      "decision": "CONFIRMED",
      "counterpart_display": "匿名 A",        // 不默认暴露对方身份
      "matches": [{"left_lines":[12,18],"right_lines":[45,52]}],
      "my_code": "...", "other_code": "..."
    }
  ]
}
```

**隐私约束**：

- 默认**不暴露对方真实姓名**，用「另一位同学」或编号；是否暴露由绑定开关控制。
- 只返回 `left_uid = me OR right_uid = me` 的记录。
- **没有绑定 → 返回 `{bound:false, items:[]}`**，前端显示为空，不报错。
- 有绑定但该学生无重复 → `{bound:true, items:[]}`，前端显示「未发现异常」。

### 7.3 前端回显

题单/比赛详情页增加「查重结果」入口：

- 未绑定 → 入口不显示（或置灰「暂无」）。
- 已绑定且无记录 → 「未发现重复提交」。
- 有记录 → 列表 + 详情（并排代码 + 高亮）。

## 8. 可视化

| 视图 | 内容 | 实现 |
| --- | --- | --- |
| **相似度矩阵** | N×N 热力图，行列为学生，颜色=相似度 | 前端 Canvas 或 SVG，>100 人时聚合 |
| **聚类图** | 按相似度连通分量聚类，识别「团伙」 | 并查集 + 力导向图 |
| **配对排行** | 按相似度降序的 Top N | 表格 |
| **并排 diff** | 两段代码行级对照 + 高亮 | 已有 `matches` 行区间；前端用代码高亮组件 |
| **题目分布** | 哪些题重复最多 | 柱状图 |

## 11. 前端（详见 08）

- 查重工作台改为「扫描列表 → 扫描详情 → 配对复查」三级。
- 创建扫描时：选范围（contest/题单/题组/单题）、阈值滑杆（含「1=不查重」说明）、语言。
- 详情页：统计卡片（覆盖题数/提交数/超阈值对数/已确认数）+ 矩阵热力图 + 配对表。
- 复查：并排 diff + AI 解释（灰色标注）+ 决策按钮。
- 绑定：单独 tab，开关式配置。
- 学生端：题单详情页「查重结果」卡片。

## 12. 实施顺序

## 13. 风险

| 风险 | 缓解 |
| --- | --- |
| 误判伤害学生 | AI 只解释成因；必须人工确认；默认仅展示已确认 |
| 大整单性能 | 按语言/题分组并行；单题上限；`--cluster-skip` 已用 |
| 快照过期 | 快照不可变；提示「扫描于 X 时，之后提交未覆盖」 |
| 隐私泄露 | 学生只查自己；对方身份可选隐藏；导出需权限 |
| 绑定冲突 | 唯一约束 + 改绑需显式解绑 |
