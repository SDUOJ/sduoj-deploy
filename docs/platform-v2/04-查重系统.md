# 04 查重系统

> 扫描快照、人工判断与向学生发布分开。JPlag 是确定性路径，不因无 AI 端口而停用；AI 只给参考解释，不自动判罚或写成绩。

## 1. 当前链与范围

reviewed plagiarism.py 已有不可变 native 快照、哈希验证、JPlag 调用和教师复查/写回。当前 scan 内限制 2–1000 条，部分入口放到 2000 但不代表执行器已支持；v2 初期保持更小的有效上限，扩大前做实际容量测试。

同一 operation_key 的重试应幂等，改变输入应 409；新一次扫描必须新 operation_key 和新 snapshot。这不应被误写为“系统不允许同题多次扫描”。v2 新增的是清晰的范围编排、历史索引与发布绑定。

| 范围 | 固定的上下文 | 取数 |
| --- | --- | --- |
| 单题 | 类型化 uid + 源/题项上下文 | 原授权提交接口 |
| 题组 | native gid + 当时题项清单 | 仅该组对应正式提交 |
| 题单 | psid + 题组/题项版本 | 原显示下标解析到 native 绑定 |
| contest | contestId + 赛题 slot/code + 截止时间 | 待新增经授权分页接口，不能假定 /internal/submission/page 已存在 |

取数只包含正式业务提交，不含 IDE Run、云保存或其他 Task 类型。必须验证每个范围的当前管理权限，不能凭知道 pid/ref_id 调用通用内部 RPC 批量取代码。

## 2. 模型、快照和分片

DDL 以 [06](06-数据库变更汇总.md) 为准：scan、scope_item、pair、decision_log、binding。snapshot 复用原不可变数据链。

- Scan 保存选择策略、时间截点、范围 manifest/hash、引擎版本/选项、languages、capture_floor、结果完整度与资源预算。
- 同 uid 在不同题组/题单 slot 重复引用时，scope_item_key 分开；按题项与语言分片，不能把整场不同题目的代码混在一次比较中。
- selection_policy=latest 或 best，明确稳定 tie-break（得分/创建时间/ID）；只取已结束且有代码的正式提交，编译失败、base code、空代码的纳入策略冻结在 manifest。
- 快照保存源提交 ID、主体 ID、代码哈希与时间；扫描后新提交不自动进入旧结果。JPlag 使用 s-<index> 匿名目录名，真实身份映射仅在授权服务端持有。
- C/C++/Python/Java 归一到引擎支持的语言 profile，未知模板明确跳过并报告，不随意跨语言比较。
- 单题初期 ≤1000；整单总量和分片并发另设上限。一个 1000 人分片最多 499500 对，不能用“每年十万行”估容量。限制比较数/报告字节/执行时间，超限失败或报告 partial，不能静默截断后宣布完整。

## 3. 阈值与完整性（S5-04）

当前命令同时传 `-n -1` 和 `-m threshold`。前者保留符合存储条件的报告比较数，后者仍会删掉低于保存下限的比较。[JPlag v6.3.0 官方参数](https://github.com/jplag/JPlag/blob/v6.3.0/README.md)明确区分这两项，因此“降低阈值无需重跑”不是现有能力。

| 参数 | 语义 |
| --- | --- |
| capture_floor | 引擎保存下限，属于不可变执行输入 |
| review_threshold | 管理端可调整的复查筛选阈值 |
| threshold_operator | v2 明确使用 gt（严格大于）；旧扫描的 ge 记录为 legacy，不重解释 |
| threshold=1 | 用户明确的不查重 sentinel；不执行引擎，Scan=skipped，TaskJob 可 success 且结果标 skipped |
| result_complete | 是否已完整采集该范围；不含未跑/失败分片不能判 complete |

需要任意降低阈值的扫描，必须以 capture_floor=0 和足够的存储/计算预算生成完整结果。若目标低于已保存 floor，则 409 requires_rescan 或显式新扫；不能把遗漏的比较当成低相似度。提高阈值只改管理视图，人工 decision 不删除。

gt 与 ge 在相等边界不等价。验收用 threshold−ε、threshold、threshold+ε 和 1；保留 full precision 后再显示百分比，不能先四舍五入判定。阈值代表相似性筛选，不等于抄袭概率，不给未经数据支持的通用误报率结论。

## 4. 人工复查与写回

状态 PENDING→CLEAR/SUSPICIOUS/CONFIRMED；改判需 expected_version、必填理由和追加 decision_log。确认一对代码前应展示扫描时间、采样政策、base code、引擎和匹配区间；AI 解释单独标“参考，不构成处理依据”，可失败而不影响人工路径。

Pair 唯一键含 scan、scope_item、language 与规范化源提交对；不能仅用两位学生 ID 合并不同题/不同次提交。跨语法文件和行区间使用原文件映射，前端不能把它们误当普通文本 diff 的相同位置。

原生题单 writeback 保留原全部复查/overwrite_existing 等门禁，并固定目标版本与每项 receipt。contest 先提供只读审阅和绑定，**不自动改比赛成绩**；若日后增加比赛写回，单独提案与验收。HTTP 超时先核查，不通过重复写回猜结果。

## 5. 发布绑定与学生隐私

绑定是“发布决定”，不是把可变 scan 暴露给学生。binding 固定 scan/review revision、范围 manifest 和审核政策；同一 kind/ref 最多一个 active 绑定。新建默认 visible=false、show_code=false；未完成、skipped、partial 或未审核的扫描禁止发布。

修改管理阈值/人工决定后生成新发布修订，学生继续看旧冻结版本，直到教师显式重发；解绑、撤销立即停止新读取。绑定范围必须与扫描范围一致，不能拿另场 scan_id 挂到任意题单。

### 5.1 学生结果

- 只读当前会话本人、当前场次成员资格及其参与的已批准记录；ref_id、pair_id 和 student 参数都不能越权。
- 默认不返回对方姓名、学号、userId、提交 ID或代码；匿名标签不应是可跨场跟踪的稳定身份。
- 允许显示相似度和本人匹配片段。即使教师开启“查看对照”，仍需独立的对方代码披露权限与发布确认，不能仅靠前端隐藏原 other_code 字段。
- 无绑定返回 bound=false；已绑定且本人无记录，只能说“本次已发布扫描未发现超阈值记录”，并显示覆盖时间/范围。不能把未知或不完整扫描显示成“无异常”。
- 提供教师联系/申诉入口；自查结果不自动形成处分或影响考试评分。

示例（权限裁剪后）：

```json
{
  "bound": true,
  "publication_revision": 3,
  "snapshot_at": "<UTC timestamp>",
  "coverage_complete": true,
  "show_similarity": true,
  "items": [{"problem_uid":"prog:123", "decision":"CONFIRMED", "similarity":"0.9200",
             "counterpart_display":"另一位同学", "my_matches":[{"start":12,"end":18}]}]
}
```

## 6. 可视化与导出

| 视图 | 约束 |
| --- | --- |
| 配对表/并排代码 | 授权管理端读取，分页，文本转义，原文件/行区间映射 |
| 相似度矩阵 | 固定题项和语言，超过阈值的人数用聚合/分页，不渲染全场巨大 N×N DOM |
| 相似网络 | 仅描述相似连接，不把连通分量直接标“团伙” |
| 题目分布 | 同时显示覆盖数、失败/跳过分片，不能只画成功项 |
| CSV/Excel | 与当前筛选和 revision 一致，记录导出审计，所有非可信字符串防公式注入 |
| .jplag/PDF 摘要 | 原包只对授权教师开放，下载短期受控；PDF 可选，不成为核心依赖 |

报告 ZIP/JSON 和代码也不可信；限制展开比、文件路径、文件数与解析内存。报告链接不能公开 bucket，也不把学生代码发到外部在线 viewer。

## 7. 前后端与实施

扫描列表→详情→配对复查→独立绑定发布；自查卡片与管理工作台是不同投影。API、错误子码和 GET/POST 约束以 [07](07-API清单.md) 为准，前端见 [08](08-前端改造方案.md)。

顺序：单题/组与快照 → 多题语言分片 → contest 授权取数 → floor/阈值/完整度 → 复查 CAS → 导出 → 冻结绑定/本人自查 → 新扫历史。各项不等待 AI；解释需经所选端口准入与费用确认。

验收：同一题多 slot、不同语言、Run/云保存排除、分页完整性、pair 唯一、取消与过期 worker、降低 floor 反例、阈值等号、发布后再改判、跨学生/跨场次/未发布读取、公式注入和未知取数状态。必须有真实 Java/Autolab 合同和数据库并发证据。
