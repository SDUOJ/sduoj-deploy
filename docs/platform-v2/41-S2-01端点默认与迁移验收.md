## 实现与原证据核对

`auto_ai_port.default_owner_id` 为 STORED 生成列，仅 active + is_default=1 时取 owner_id，其余为 NULL；唯一约束允许同一用户多个非默认端点。`ports._request` 先创建/锁定稳定账户行，串行默认替换、停用、删除、CAS 与回执；旧默认在目标 flush 前清除，enable 不恢复默认，不选备用。

迁移 `d1b201d` 的精确归档审计为 53 passed，包括真实 MySQL 的生成列、多 NULL 唯一性、旧列类型/排序规则、InnoDB、CHECK ENFORCED、备份身份/hash 与重入；该总数包含治理等其他范围，不将 53 全称为端点测试。此前旧迁移旁路和未执行 CHECK 缺陷的失败证据、修复与审计结论保留。

端点 `929e0ed` 精确归档为 46 passed，包含原 2 项真实 MySQL 多进程：零账户/零端点的同操作回执去重、并发默认替换。该总数也包含 owner/API 等范围，不与当前测试相加。当前 `port_migration.py` 字节与 `AiPort` AST 均与已审计 `d1b201d` 相同，已在 `s2-01-prior-evidence-crosscheck.json` 断言，不以旧源码的结论替代变化后的实现。

原 SQL dump 18499 字节，SHA256 `8ffa30d907ac48b47a1067c46fe29b34e505ccda9d605139a98ca8820521b051`，仍与备份 manifest 和迁移结果一致。原恢复记录实际还原 15 张旧表、runtime 行及无 port 列的旧 schema，并清理自有恢复库。本轮仅复核 hash/原记录，不重新跑已收敛的备份恢复；原审计明确写出未独立重演的限制。

## 本批补齐的缺口

测试提交 `35909b1` 的 `test_port_default_lifecycle_mysql.py` 在当前 MySQL **8.0.43** 上 **3 PASS、0 FAIL/SKIP**，1.61 秒。各用独有随机库，两个并行请求来自独立 Python 进程；不调用 provider/SDK、不替换权限实现、不接共享业务库。

- default 与同版本 disable 或 delete 竞争：仅一项成功，另一项 404/409；最终恰有一个有效默认。若生命周期动作获胜，原默认未被无故改动；若 default 获胜，旧默认清除、目标版本正确，旧版本操作不能覆盖。
- `_receipt` 前模拟 flush 后失败：整个事务回滚，两个端点默认值/版本不变；相同 operation key 随后能成功并重放，另一 stale key 拒绝，无隐式备用选择。

删除分支依赖 TaskJob 的 status；本测试给既有最小任务 stub 补 status 列，只是自有库夹具初始化，不是产品 DDL。fixture 最终 DROP 本次随机库，测试 teardown 无错误。没有新产品缺陷，不伪造本批 red；历史已修缺陷的 red/green 仍保留。
