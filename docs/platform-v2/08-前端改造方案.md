# 08 前端改造方案

> 技术栈：React + TypeScript + Ant Design + i18next。
> 约定来自现有实现：`src/Utils/API/*.ts` 封装请求、`src/Config/router/*.tsx` 注册路由、`src/Assert/lang/{zh,en}.json` 双语文案、`Pages/Manage/AI/` 每页配同名 `.css`。

## 1. 现有骨架（按此照抄）

### 1.1 路由注册

```tsx
// src/Config/router/routerM.tsx
{
  id: 9414,
  path: UrlPrefix + '/manage/problemSet/xxx',
  exact: true,
  title_i18n: 'aiMenuXxx',
  component: aiPage(() => import('../../Pages/Manage/AI/XxxWorkbench')),
}
```

- `aiPage()` 包裹 → 自动套用 AI 工作区的访问边界（`AIRouteBoundary`）。
- `devOnly: true` 表示仅开发环境可见（现有 AI 页多为 devOnly，正式开放时去掉）。
- 学生端页面注册在 `router.tsx`。

### 1.2 API 层

```ts
// src/Utils/API/ai-xxx.ts
import request from './request';
const base = '/ps/auto-task/ai';
export const xxxApi = {
  list: () => request.post<{ rows: X[]; totalNum: number }>(base + '/resources/list', {...}),
  get: (id: string) => request.get<X>(base + '/resources/' + id),
  create: (b: Create) => request.post<{ taskId: string }>(base + '/xxx/create', b),
};
```

- 统一解包 `{code, data, msg}`；失败由 `request.ts` 统一提示。
- 管理端请求自动带 `withCredentials`（Cookie 会话）。

### 1.3 页面骨架

```tsx
<Layout className="xxx-workbench">
  <AIWorkspaceNav active="xxx" />
  <Layout.Content>
    {/* 标题 + 操作区 + 表格/表单 + 空状态 */}
  </Layout.Content>
</Layout>
```

配套 `xxx-workbench.css`，避免全局污染。

### 1.4 文案

`zh.json` / `en.json` 同时新增，key 前缀统一（如 `aiPort*`、`aiPlagiarismScan*`、`invigilator*`）。已有测试 `locale-smoke.test.tsx`、`locale-source.test.ts` 会校验两语言 key 一致。

## 3. 关键交互设计

### 3.1 AI 端口页（#1）

```
┌ 我的 AI 端口                            [+ 新建端口] ┐
│ ● 我的 DeepSeek   deepseek-v4.1-flash   默认           │
│   并发 2/2 · 今日 34 次 · 连接正常   [测试][编辑][删除] │
│ ○ 备用端口        gpt-5.6-sol           —              │
│   并发 0/1 · 今日 0 次 · 未测试      [测试][设为默认]  │
└────────────────────────────────────────────────────────┘
未配置时：整页显示引导卡片「平台不提供默认 AI，请先配置你自己的端口」
```

**交互要点**：

- 新建/编辑用 Modal + Form；`api_key` 输入框 `type=password`，编辑时占位显示 `sk-****abcd`（`key_fingerprint`），**留空表示不修改**。
- `wire_api` 固定 `responses`，仅展示不可改（若后端允许兼容模式，再放开）。
- 「测试连接」按钮：转圈 → 成功显示延迟，失败显示原因（不回显响应体）。
- 设为默认：若已有默认，弹二次确认「将替换现有默认端口」。
- 并发输入用 `InputNumber`，范围 1–32，旁注「该端口同时最多处理的任务数」。

### 3.2 题目中心（#2）

```
┌ 题目中心                                          [新建题目 ▾] ┐
│ [ 公开题库 ] [ 我的组 ] [ 我的 ]        [全部(超管)]           │
│ 类型: [全部][编程][客观][主观]  标签:[...]  难度:[...]  🔍     │
├──────────────────────────────────────────────────────────────┤
│ [编程] SDUOJ-123  某题      通过 12/340  ●公开                │
│ [客观] 选择题 45   某某      单选 4 选项 ●组内                │
│ [主观] 简答题 46   某某      文本作答   ●私有                 │
└──────────────────────────────────────────────────────────────┘
```

- 三个 tab 对应 `source=public|group|mine`；`all` 仅超管可见。
- 卡片左侧类型角标（编程/客观/主观），颜色区分。
- 可见性用彩色圆点 + 文案（公开/组内/私有）。
- 空状态：公开题库为空时提示「暂无公开题目」，而非空白。

### 3.3 出题工作台（#4）

```
┌← 返回        题目：二叉树的最近公共祖先         [预览] [发布] ┐
│ ① 思路 ✓   ② 题意 ✓   ③ 题面 ●   ④ 元数据    ⑤ 程序          │
│ ⑥ 数据     ⑦ 终检     ⑧ 实测     ⑨ 发布                       │
├──────────────────────────────────────────────────────────────┤
│ 右侧：当前阶段编辑区（Markdown 编辑器 / 表单 / 代码块）        │
│ 底部：[AI 起草] [保存] [进入下一阶段]                          │
└──────────────────────────────────────────────────────────────┘
```

- 左侧竖向步骤条，已完成打勾，未开始置灰，当前高亮。
- 「进入下一阶段」在准入条件未满足时禁用并提示原因。
- 终检页用检查清单展示七项，每项 `通过/失败/未运行` + 详情展开。
- 实测页显示「已测 2/3 人」+ 每条记录（用时/得分/意见）。
- 发布按钮为 `type=danger`，二次确认列出将要写入的字段。

### 3.4 文档解析对照（#5）

```
┌ 源文件.pdf ─────────────────┬─ 解析结果 ─────────────┐
│ ┌──────┐                     │ 1. 下列…（客观题）      │
│ │ 页面 │  ← 高亮当前块       │    选项 A/B/C/D         │
│ │ 截图 │                     │    答案 A  ✓已识别      │
│ └──────┘                     │ 2. 请简述…（主观题）    │
│ [上一块][下一块]             │    评分标准 …           │
└──────────────────────────────┴────────────────────────┘
```

- 左栏 PDF 用 `pdf.js` 渲染指定页 + 画 bbox 高亮。
- 右栏可编辑（修正模型误判）。
- 每个块标 OCR 置信度，低于阈值标黄提示人工核对。
- 翻译按钮切换「原文/译文/双语」。

### 3.5 查重扫描详情（#8）

```
┌ 2026 预推免机试 · 第一次查重        阈值 0.70  [调阈值] [导出] ┐
│ 覆盖 6 题 · 214 份提交 · 超阈值 37 对 · 已确认 5              │
│ [相似度矩阵] [配对列表] [绑定配置]                             │
├──────────────────────────────────────────────────────────────┤
│ 0.97  A301/张三 ↔ A302/李四   某题   [CLEAR][SUSPICIOUS][CONFIRMED]│
│ 0.91  ...                                                     │
└──────────────────────────────────────────────────────────────┘
```

- **并排 diff**：点击配对打开 Drawer，左右两栏代码 + 行号 + 高亮 `matches` 区间。
- **相似度矩阵**：Canvas 热力图，点击格子跳对应配对。
- AI 解释放独立折叠区，灰色 + 《仅供参考》标签。
- 决策必须填理由；改判记入历史。
- 「调阈值」是**重新筛选**（不重跑），即时生效。

### 3.6 监考端（#12，移动优先）

```
┌────────────────────────┐
│ 青岛 A301 · 2026 预推免 │  ← sticky
│ 14:05  已登录 213/216  │
├────────────────────────┤
│[全部][异常][未登录][未交]│  ← 分段控件
├────────────────────────┤
│ 3  张三   ● 在线  ✓已交 │
│ 5  李四   ○ 离线  ⚠异常 │
│ 8  王五   ● 在线  未交  │
└────────────────────────┘
```

**移动适配规则**：

| 项 | 要求 |
| --- | --- |
| 布局 | 单列卡片，**禁止**横向滚动表格 |
| 触控目标 | ≥ 44×44 px |
| 字号 | 正文 ≥ 14px，关键信息 ≥ 16px |
| 视口 | `viewport-fit=cover`，适配 iPhone 刘海 |
| 刷新 | 下拉刷新 + 15s 自动轮询 |
| 网络差 | 显示最后更新时间；失败保留旧数据并标灰 |
| 操作 | 底部 Sheet 代替弹窗（小屏友好） |

**独立布局**：监考端**不加载** `MLayout` 与管理端导航，单独一个轻量路由树，减少首屏体积。

### 3.7 学生查重卡片（#10）

```
┌ 查重结果 ────────────────────────────┐
│ 本次考试共发现 1 条需要说明的记录     │
│ 某题 · 与另一位同学相似度 92%         │
│ [查看对照]                            │
└──────────────────────────────────────┘
```

未绑定时**整个卡片不渲染**；绑定但无记录时显示「未发现重复提交」。

## 4. 状态与数据流

| 场景 | 方案 |
| --- | --- |
| 任务轮询 | 复用现有 2s 轮询（`PlagiarismWorkbench` 已有模式）；终态停止 |
| 监考端 | 15s 轮询，页面隐藏时暂停（`visibilitychange`） |
| 长列表 | 服务端分页，`Table` 的 `pagination.serverSide` |
| 乐观更新 | **不使用**。写操作一律等接口返回后刷新 |
| 错误 | 统一 `message.error` + 页面级 `Alert`（重试按钮） |
