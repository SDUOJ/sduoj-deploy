## 缺陷与修复

原 `ProblemCommonService` 使用 `List.hashCode()` 作为管理组查询缓存键。`[1,32]` 与 `[2,1]` 的 hash 均为 1024，第二位用户可能继承第一位用户的题目 ID 列表。外层按组缓存和内层全量题目权限映射还会保留撤权前的数据。

批准方案让学生列表、管理列表，以及正式提交列表使用的私有题排除查询，在最终 SQL 中匹配当前 `p_manager_groups`。组 ID 规范化、去重后作为参数绑定，空集合不授予权限；不在分页后过滤。移除两层权限结果缓存的三个 `@Cacheable`，兼容方法保留但直接查询数据库。其他角色、API、非权限缓存及构建流程不变；不要求清空 Redis。
